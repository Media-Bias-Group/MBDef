{\LARGE\bfseries MBDef-Gold: annotated ground truth}\\[5pt]
{\small The hand-labelled ground truth of MBDef \enspace\textperiodcentered\enspace version 1.0.0}
\end{center}
\vspace{-4pt}
The main dataset, \textbf{MBDef-Gold}, contains \textbf{1,003 concept records from 130 papers},
with \textbf{1,192 definitions and 387 examples}. Another 1,325 valid but non-relevant
records are stored separately. A \emph{record} describes one concept in one paper;
it can contain several definitions and examples.

V3 was a synthetic extraction dataset. Annotators recorded judgments and comments
in separate Label Studio exports; their comments did not directly rewrite V3.
Curation selected records and applied approved edits to their fields. The final
files retain \textbf{V3's JSON structure}, paper metadata, IDs and train/test assignments.
MBDef-Gold stores exactly 130 papers; 20 entries with no retained records were removed.
The non-relevant file still stores 150 entries: 135 with records and 15 empty. The sets
overlap in 115 papers because relevance is judged per concept, not per paper.

\smallhead{How the annotations were used}
Two annotators assessed each record. Disagreements on \emph{is a definition} or
\emph{is relevant} received a third independent annotation (931 records).
This did not resolve every disagreement about individual supporting fields.
The curator handled notes, field issues and corrections, and accepted the remaining
agreed or majority outcomes. Original annotations, rejected records and edit history
are preserved in the release archive.

\smallhead{Reading these changes}
Edits include corrections and moves between fields, as well as additions and
removals. There are 31 moves where the complete text and citation are unchanged;
moves accompanied by edits are not counted in that number. Net item counts alone
cannot distinguish these operations.

Keeping V3 can also be an explicit decision: \emph{Description bias} retains its
full sentence and the citation marker \file{\{McCarthy, 1996 \#xxx\}} because that
marker is already broken in the source. An annotation comment is not itself a
replacement value in the GT.

\smallhead{What to use and what to keep}
Use \file{validated\_gt.json} for the relevant-definition training target.
Keep \file{validated\_gt\_non\_relevant.json} separate:
its definitions were judged valid, but supporting fields were hidden when an
annotator marked a concept irrelevant, so those fields did not receive the same
review. Relevance labels and annotation notes remain in the accompanying evidence,
outside the training records.

The release archive \file{validated\_gt\_release.zip}, which the build of this release writes,
contains both datasets, this report, statistics, historical JSONs, the original export and all
annotation/edit evidence. \file{SHA256SUMS} lists checksums for its contents. MBDef-Gold omits 20 empty paper
entries and sets \file{paper\_count} to 130; all retained paper and record values are
unchanged. The non-relevant file and original export are preserved exactly.
