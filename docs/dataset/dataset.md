# MBDef, the dataset: `mbdef dataset`

| | |
|---|---|
| **Paper step** | The released dataset MBDef: the media-bias terms that Step 5 keeps, merged into concepts, as tables with a dataset card, and the same tables as JSON; and MBDef-Gold's split files and dataset card |
| **Code** | [`src/mbdef/dataset/`](../../src/mbdef/dataset/): `build.py` (the tables, their checks and the validation report), `store.py` (what the build reads from the corpus store), `card.py` and `cards/` (the dataset cards: one template folder per dataset, `mbdef/` and `gold/`, laid out as the files of the upload), `export.py` (the JSON copy), `gold.py` (MBDef-Gold's split files and card, with its sample records), `schema.py` (the tables' columns and types); the parser is in `cli.py` |
| **Commands** | `mbdef dataset build`, `mbdef dataset export`, `mbdef dataset build-gold`; `dataset <action> --help` lists each action's flags |
| **Checked by** | `tests/test_dataset.py` (a miniature, byte for byte with its expected files); the real corpus tables byte for byte with version 1.2.1 ([below](#how-it-was-checked)) |

## What it does

Step 5 ([postprocess.md](../step-5-post-processing/postprocess.md)) decides for each of the corpus's 67,394 Extracted Concepts (a term as one paper defines it) whether it is about media bias, and merges the kept ones whose labels are the same up to spelling.
`dataset build` turns that into the published dataset: 62,066 kept Extracted Concepts with their 103,476 definitions from 6,115 papers, merged into 34,916 merged terms (the dataset's "concepts"). It writes five tables as parquet files, a dataset card (`README.md`, the page a dataset host shows) and `provenance.json`.
`dataset export` writes the same tables as JSON files, which need no parquet reader.
`dataset build-gold` writes the hand-labelled ground truth, MBDef-Gold (2,328 records), as a dataset of its own: its three split files and its card ([below](#mbdef-gold-dataset-build-gold)). MBDef holds no ground truth; its card links MBDef-Gold.

The published dataset is MBDef, version 1.0.0, on Hugging Face ([`mediabiasgroup/MBDef`](https://huggingface.co/datasets/mediabiasgroup/MBDef), named with MBDef-Gold's repository in `HF_DATASETS` in [`files.py`](../../src/mbdef/files.py), which pins the revision of the upload); git holds the code that builds it, not the dataset. Both repositories are private for now.
`uv run mbdef data fetch MBDef/` downloads its five tables into `$DATA_ROOT/MBDef/data/` and the MBDef Explorer's page data into `$DATA_ROOT/MBDef/explorer/`, and checks each file's sha256 ([data-fetch.md](../setup/data-fetch.md#the-two-datasets)).
Each card opens with its own banner, which the build copies into the dataset folder as `assets/banner.png`: MBDef's is `docs/images/mbdef-banner.png` (the MBDef Explorer's map), MBDef-Gold's `docs/images/mbdef-gold-banner.png` (its own records and splits). Under it is a centred row of two buttons: on MBDef's card *Open the MBDef Explorer* and *Project page* (`BADGES` in [`card.py`](../../src/mbdef/dataset/card.py), built from `EXPLORER_URL` and `PROJECT_URL` in `dataset/__init__.py`; the repository's README.md shows the same row under its poster, which a test checks); on MBDef-Gold's, which is not about the Explorer, *The main dataset: MBDef* and *Project page* (`gold_badges`). The cards then link the paper, the code (both placeholders until they are public: `PAPER_URL` and `CODE_URL` in `dataset/__init__.py`), each other, and on MBDef's card the [MBDef Explorer](https://media-bias-group.github.io/MBDef/) and the [project page](https://media-bias-group.github.io/MBDef-ProjectPage/).

**A card is an overview and its pages.** `README.md` is short: what the dataset is, its tables, how to load it, the limits in two lines, the licence and a table of the pages. Everything else is one page per topic in `docs/`: for MBDef `tables.md` (with the worked example), `columns.md`, `how-it-was-made.md`, `relevance.md`, `term-merging.md`, `terms-view.md` and `licence.md`; the evaluation and the limits are left to the paper; for MBDef-Gold `what-it-holds.md`, `files-and-columns.md`, `limits.md` and `licence.md`. The README links each page by its address on Hugging Face (`https://huggingface.co/datasets/<repo>/blob/main/docs/<page>.md`; `files_url` in `card.py`), so the links work from the JSON copy and from a copy of the card too, and a test checks that every such link names a file the build wrote and that the README links every page.

**MBDef-Gold's samples.** Its README has a *Samples* section: a picture (`assets/samples.png`, from `docs/images/mbdef-gold-samples.png`) and, folded away in a `<details>` block, a table of 32 records of the train split. `gold.samples` draws them with a fixed seed: 16 relevant and 16 not relevant, each from a different paper, from records with a paper title and a first definition of 60 to 300 characters; the test split is never sampled, so no test text is on the card. A table cell is escaped so that no text reads as Markdown (`gold.markdown`) and a definition is cut after 200 characters. The picture shows six of the 32 (`gold.poster_samples`: the first three of each label, with a split vote among them), so that the picture and the table cannot disagree; the picture is made outside this repository by a script that calls `gold.samples` on the released split files, and `build-gold` copies it (`--samples-image`, or `--no-samples-image`).

What the dataset holds: every definition text verbatim, but no paragraph context or other text of the papers; only the Extracted Concepts Step 5 keeps, each with its three member scores, their reference ranks and the ensemble score; CC BY 4.0 for what the project made (the definitions stay quotations of their authors).

| Table | One row is | Rows |
|---|---|---:|
| `terms` | a merged term (below) with everything its papers say about it: definitions, description, synonyms, related terms, subtypes, supertypes, examples, each item merged across papers, with how many papers state it and the concept a name links to | 34,916 |
| `concepts` | a merged term: the kept Extracted Concepts (a term as one paper defines it) whose labels match under the adopted version of the Label Match rule (stored as `C-20261021`, [postprocess.md](../step-5-post-processing/postprocess.md#two-versions-of-the-label-match-rule)); a Label Group restricted to its kept members, not a Media Bias Concept (the table keeps the name it was released with) | 34,916 |
| `instances` | a kept Extracted Concept, with its scores and every other extracted field | 62,066 |
| `definitions` | one definition of an Extracted Concept, as the paper words it, with the references it cites | 103,476 |
| `papers` | a source paper: DOI, title, year, OpenAlex id, open-access status and licence | 6,115 |

**Worked example: "fake news".** The merged term `gf8d45d620d38` ("fake news") joins 6 spellings ("fake news", "Fake news", "Fake News", "Fake news (FN)", "fake-news", "fake news (FN)") over 659 Extracted Concepts from 659 papers, with 1,891 definitions; its `merge_flags` say a bracketed acronym was dropped to join them. One of its rows is `m08713153bd204656`: "Fake news" in a seed paper of 2026 (DOI 10.3389/fcomm.2026.1790164, licence cc-by, 14 kept rows and 31 definitions in that paper). Its member scores are 0.988 (embedding classifier), 0.997 (the decision model basal, an LLM that answers core, satellite or irrelevant) and 1.000 (the retrieval judge; the three are [postprocess.md](../step-5-post-processing/postprocess.md#the-ensemble)'s ensemble); placed among each member's 1,700 train + dev scores they are the reference ranks 0.975, 0.936 and 0.991, and the ensemble score is 0.344 × 0.975 + 0.339 × 0.936 + 0.316 × 0.991 = 0.967. That is above the keep cut 0.4150 and above the stricter best-F1 cut 0.5850, so the row is kept and `strict`. It has 3 definitions in `definitions`; the first (`o04be1d9f462da565`, 173 characters) cites "Mara, 2019, p. 4". In `terms`, the row of "fake news" merges what all 659 papers say: 1,891 definitions become 1,707 items (texts that read the same once case, punctuation and spacing are set aside are one item), and its most stated supertype is "disinformation" (38 papers), which `links_to` the concept `g7f2fbf4abd1a`, "disinformation".

## Run it

```bash
uv run mbdef data fetch frozen/artifacts/experiments/taxonomy-curation-v2 \
    frozen/closure/definition-corpus-v1.1 frozen/step5-post-processing MBDef-Gold/   # the store, release v1.1, Step 5, MBDef-Gold
uv run mbdef dataset build --out runs/dataset       # runs/dataset/taxonomy-dataset/, validation.{json,md}
uv run mbdef dataset export --out runs/dataset      # runs/dataset/taxonomy-dataset-json/
uv run mbdef dataset build-gold --out runs/dataset # runs/dataset/MBDef-Gold/, gold-validation.{json,md}
```

All three run on a CPU: the build takes about 1.5 minutes, the export 20 seconds, `build-gold` a few seconds. `--same-data-as data/frozen/dataset/release-1.2.1.sha256` on `build` or `export` compares every file written with the hash the listing records: the build adds it to its checks (and fails if a table differs), the export exits 1 and names the files that differ. Files the listing records that are not written (1.2.1's ground-truth tables and their JSON copies) are named, not counted as a difference.

Flags of `build`: every input has one, whose default is the file of the adopted run ([Inputs](#inputs)):
`--decisions`, `--label-groups`, `--term-merging`, `--pick`, `--store`, `--corpus`, `--recorded`, `--ground-truth`, `--non-relevant`. The settings are `--licence` (default `cc-by-4.0`), `--repo-id` (the dataset's repository on Hugging Face, which the card's loading example names; default `mediabiasgroup/MBDef`, from `files.py`) and `--gold-repo-id` (MBDef-Gold's repository, which the card links; default `mediabiasgroup/MBDef-Gold`), `--banner` (the image at the top of the card; default `docs/images/mbdef-banner.png`; `--no-banner` leaves it out) and `--explorer-data` (the Explorer's page data, [below](#outputs)). `--out` must not be inside a frozen folder.
Flags of `build-gold`: `--ground-truth`, `--non-relevant`, `--votes`, `--recorded` (defaults as for `build`), `--licence`, `--repo-id` (default `mediabiasgroup/MBDef-Gold`), `--mbdef-repo-id` (MBDef's repository, which its card links), `--banner` (default `docs/images/mbdef-gold-banner.png`), `--no-banner`, `--samples-image` (default `docs/images/mbdef-gold-samples.png`) and `--no-samples-image`.

The OpenAlex answers are the lookup's output as it was saved: one line per batch of up to 50 DOIs asked, with the works found (fields `id`, `doi`, `publication_year`, `type`, `open_access`, `best_oa_location`, `primary_location`, `locations`), and one line per DOI asked again alone where a batch was refused: 401 lines, 5,344 DOIs asked, 5,218 works found. The merges likely wrong are the merge audit's list, byte for byte.

### What is read from the store

An item (a definition, or an item of another field) belongs to the dataset when at least one of its sources is a P≥28 extraction (release v1.1's variant whose records passed the Qwen verifier and then the relevance filter: the extractor's configuration selected for at least 28% precision on the TEST papers, [selection.md](../step-3-extraction/selection.md); the corpus release v1.1 is Step 4's release folder, [extract.md](../step-3-extraction/extract.md)); that is the rule by which `postprocess` reads the definitions too. Its citation list is the one the P≥28 run wrote, in the order of its places, each marker once. The store also keeps one list per item from whichever run was ingested first, often the P≥20 run (the configuration selected for at least 20% precision), which reads with more passes and adds markers; 8,208 items differ that way, and the build counts them. Only the tables `papers`, `mentions`, `occurrences` and `occurrence_sources` are read: no paragraph context and no other text of the papers. A store that holds no paper text is enough. Version 1.2.1's card also counted the definitions not found verbatim in their paper's parsed text (326) or only in part (20), from the store's paragraph contexts; this build reads no paper text, so it leaves that count out.

| Key | Copied from |

| `test.records`, `relevant`, `papers` | the final TEST comparison (`records`, `relevant`, `papers`): 628 records, 310 relevant, 32 papers |

| `test.difference` | the ensemble row's `delta_vs_reference`: AUC +0.0107 [+0.0007, +0.0240], precision +0.101 [+0.041, +0.158] |
| `test.comparisons` | the number of methods its decision compared with the classifier: 12 |
| `test.reads` | the entries of the TEST read log (`test-reads.json`, not part of this repository): 21; both cards quote it |
| `train_dev` | the reference scale with basal's reference scores from the H200 GPUs its corpus run used: its 95%-recall and best-F1 cuts (the build checks they equal `ensemble.json`'s), the train + dev AUC on reference ranks (0.9272) and within the batch (0.9333), and recall, precision and kept share at both cuts |
| `merge_audit` | the merge audit: 26 singular-plural pairs the rule leaves apart (168 kept terms), and 76 word-order merges whose main words differ |

## Outputs

`dataset build --out OUT` writes:

| File | What it is |
|---|---|
| `OUT/taxonomy-dataset/README.md` | the dataset card, an overview: YAML front matter for a dataset host (one config per table) and the body from `cards/mbdef/README.md` |
| `OUT/taxonomy-dataset/docs/*.md` | the card's pages, one per topic, from `cards/mbdef/docs/`; every number is computed in the build and every worked example is a real row |
| `OUT/taxonomy-dataset/data/{terms,concepts,instances,definitions,papers}.parquet` | the five corpus tables (zstd level 19, with statistics) |
| `OUT/taxonomy-dataset/provenance.json` | the version, settings, code commit, Python, polars and pyarrow versions, and every input and output with its sha256 (paths relative to the repository or as `$DATA_ROOT/...`) |
| `OUT/taxonomy-dataset/assets/banner.png` | the banner at the top of the card (`--banner`), shown by a relative address, so that a private repository shows it to its members |
| `OUT/taxonomy-dataset/explorer/` | with `--explorer-data FOLDER`: the MBDef Explorer's page data, copied from FOLDER (what `explorer build` writes to `explorer/data/`) after the checks below; the card then says what it holds |
| `OUT/validation.json`, `OUT/validation.md` | the checks and their outcome, and every table's rows, bytes and sha256 (not part of the dataset) |

With `--explorer-data`, the build also checks the page data the way `explorer build` does ([explorer.md](explorer.md)): every file has the sha256 its `SHA256SUMS` lists, the page data holds exactly the rows of the tables just written, with the same scores, definitions, concepts and papers, and it holds no run history (commits, run times, local paths), which `explorer build` leaves out of what it writes.
A failing check moves the folder to `OUT/taxonomy-dataset-FAILED/` and the command exits 1. The checks compare every count with the decisions and the term merging, recompute the Label Match rule's groups, keys, normalisation steps and `joined_by` and compare them with the stored ones, count the extracted items again in SQL, check that `terms` holds every item once and only under its own concept, that the tables hold no dropped row, no private column and no absolute path.
`schema.py` fixes every column and type; the card's "Columns" section explains them.

`dataset export --out OUT` writes `OUT/taxonomy-dataset-json/`: `terms.json` (106 MB; empty parts of an item are left out, so an entry reads like a page about its term), `papers.json` and `tables/{concepts,instances,definitions}.json` (every parquet column), each read back and compared with its table; `SCHEMA.md` (the JSON files, with one entry shortened), `DATASET-CARD.md` (a copy of the card) and `SHA256SUMS`.

### MBDef-Gold: `dataset build-gold`

MBDef-Gold's records, statistics, guide and report come from `groundtruth build` ([groundtruth.md](../step-3-extraction/groundtruth.md)). `dataset build-gold --out OUT` adds what a dataset host shows and loads, in `OUT/MBDef-Gold/`:

| File | What it is |
|---|---|
| `README.md` | MBDef-Gold's dataset card: YAML front matter (one config, three splits) and the overview from `cards/gold/README.md`, with the counts per split, two real records with unanimous votes, the TEST split's read count and a link to MBDef |
| `docs/*.md` | the card's pages (what it holds, files and columns, limits, licence), from `cards/gold/docs/` |
| `assets/banner.png` | the banner at the top of the card (`--banner`; default `docs/images/mbdef-gold-banner.png`) |
| `assets/samples.png` | the picture of sample records in the card's *Samples* section (`--samples-image`; default `docs/images/mbdef-gold-samples.png`) |
| `data/{train,validation,test}.parquet` | one row per record (`dev` is the file `validation`), with its label, votes, fields and paper; the columns are `ground_truth` in `schema.py` |
| `validated_gt.json`, `validated_gt_non_relevant.json` | the two record files, copied unchanged |
| `provenance.json` | settings, code commit, and every input and output with its sha256 |

and `OUT/gold-validation.{json,md}` beside it: every record has its votes, every label equals its majority vote, the record ids are unique, no private column, no absolute path. A failing check moves the folder to `OUT/MBDef-Gold-FAILED/` and the command exits 1.

## How it was checked

**Byte for byte with version 1.2.1.** Version 1.2.1 still held the ground truth in MBDef (`data/ground_truth/*.parquet` and their JSON copies); its other files are what `build` and `export` write now. The comparison below was made on a CPU, from the repository's Step 5 files and the data root, with the build that also wrote the ground-truth tables:

```bash
uv run mbdef dataset build --out runs/dataset --same-data-as data/frozen/dataset/release-1.2.1.sha256
uv run mbdef dataset export --out runs/dataset --same-data-as data/frozen/dataset/release-1.2.1.sha256
```

The build passed all 66 checks of that build (5 more lines are information) and its 8 parquet files, and the export's 8 JSON files, had the sha256 recorded for version 1.2.1 (`release-1.2.1.sha256` copies them from version 1.2.1's `provenance.json` and `SHA256SUMS`). For example `data/terms.parquet` is 12,439,076 bytes with sha256 `bc7f3105…` both times, and `terms.json` 106,194,692 bytes with `ccd5987e…`. The card of that build differed from 1.2.1's in five places: it no longer called itself a private draft, its loading example names `--repo-id`, its section on versions names only its own version (the dataset's repository on Hugging Face keeps the earlier ones), the count of definitions not found verbatim in their paper's text is left out ([above](#what-is-read-from-the-store)), and its citation is a placeholder ("Citation details will follow.") instead of an entry with a title and authors; every other number in it is the same. Those numbers are filled in, not written into the card's templates: from the built tables, the corpus view (for example its 6,479 papers, 3,869 seed and 2,610 closure, and its 110,639 P≥28 definition items, 240 of them a repeat of the same text for one term in one paper) and `card-numbers.json`, or, for the steps before this one, from the recorded numbers `EARLIER` in `card.py` (the search's 50,101 documents, the extractor's 80.5% recall on the TEST papers). **The miniature.** `tests/test_dataset.py` runs both commands on `tests/fixtures/dataset-mini/`: synthetic inputs (44 papers, 40 labels, every field, items with and without a source in the P≥28 extraction, citation lists that differ between runs, OpenAlex answers with and without a year or a licence, 8 ground-truth papers in all splits) and the parquet and JSON files these commands wrote from them (`expected/`); `build-gold` runs on the same inputs. ## How to adapt it

- **New decisions or a new term merging** (for example after rerunning `postprocess ensemble` and `merge-terms` on new scores): `--decisions runs/ensemble/ensemble.csv --term-merging runs/merged`, and `--label-groups` if the groups were rebuilt. The build checks that they agree with each other and with the store, and the card's numbers follow.
- **A new corpus**: a new store and release folder (`--store`, `--corpus`), new OpenAlex answers for its DOIs in the format above (`--recorded`, a folder with the three recorded files), and new Step 5 outputs for it. No command of this repository asks OpenAlex: the answers are recorded data, and a new lookup has to be made outside it in their format.
- **New card numbers** after a new Step 5 evaluation: a new `card-numbers.json` with the same keys, in the folder `--recorded` names (it is recorded data too: no command writes it). After new searches, selections or extractor evaluations: `EARLIER` in `card.py`. The card's text is the folder `cards/mbdef/` (`README.md` and `docs/*.md`, laid out as the files of the upload); a placeholder `{{name}}` is filled from `card.py`, and the build fails if one is left in any page.
- **A new version**: set `VERSION` in `dataset/__init__.py` (the card and `provenance.json` name it; 1.0.0 is the first version on Hugging Face), build it, and record its hashes the way `release-1.2.1.sha256` records the tables that 1.0.0 holds.
  Upload it to the dataset's Hugging Face repository as one commit and tag that commit with the version (the card describes only its own version), then put the new files' sha256 and sizes into `data/data-root.tsv` and pin the new revision in `files.HF_DATASETS` ([data-fetch.md](../setup/data-fetch.md#how-to-adapt-it)).
- **The links of the cards**: `PAPER_URL`, `CODE_URL`, `EXPLORER_URL` and `PROJECT_URL` in `dataset/__init__.py`; the banner is `--banner`.
- **MBDef-Gold's card**: its text is the folder `cards/gold/`; after a new `groundtruth build`, run `build-gold` on its record files and upload `OUT/MBDef-Gold/` to MBDef-Gold's repository with the release's other files (statistics, manifest, guide, report, figures, `history/data-README.md`), then put the files' sha256 and sizes into the `MBDef-Gold/` rows of `data/data-root.tsv`.
